ARCHITECTURE.md should contain:

1. Architecture Overview
   - System purpose
   - Architecture style
   - High-level component overview

2. Architecture Principles
   - Key principles guiding the implementation
   - Simplicity, modularity, security, testability, etc.

3. System Context
   - Users
   - External systems/services
   - Inputs and outputs
   - System boundaries

4. High-Level Architecture
   - Major components
   - Responsibilities of each component
   - How components communicate

5. Detailed Component Design
   For every major component:
   - Responsibility
   - Inputs
   - Outputs
   - Dependencies
   - Important interfaces
   - Failure behavior

6. End-to-End Data Flows
   Describe the important flows from input → processing → storage/service → output.

7. Data Architecture
   - Major entities
   - Storage requirements
   - Data lifecycle
   - Persistence vs transient data
   - Data relationships
   Do not create unnecessary schemas unless required.

8. API / Interface Design
   - Important APIs/interfaces
   - Request/response responsibilities
   - Authentication/authorization considerations
   - External integrations

9. AI/ML Architecture
   If applicable:
   - Model/component responsibilities
   - Input/output
   - Retrieval/context flow
   - Agent/tool interactions
   - Evaluation
   - Guardrails
   - Explainability
   - Failure/fallback behavior
   Do not introduce AI components unless justified by the PRD/design.

10. Security Architecture
   - Authentication
   - Authorization
   - Secrets
   - Data protection
   - Access boundaries
   - Audit requirements

11. Reliability & Error Handling
   - Failure points
   - Retry/fallback strategy
   - Graceful degradation
   - Human intervention where required

12. Observability
   - Logging
   - Metrics
   - Tracing
   - Audit logs
   - Important events to monitor

13. Deployment Architecture
   - Runtime components
   - Environment separation
   - Configuration
   - Deployment assumptions

14. Technology Decisions
   For every major technology choice:
   - Technology
   - Why it is needed
   - Alternatives considered
   - Trade-offs

15. Scalability Considerations
   - Current MVP needs
   - What could become a bottleneck
   - How the architecture could evolve

16. Architecture Risks & Trade-offs
   - Technical risks
   - Operational risks
   - Architectural compromises

17. Requirements Traceability
   - Map major architecture components back to PRD requirements
   - Map them to relevant sections of DESIGN.md

18. Open Questions / Decisions Required
   - Anything that must be clarified before implementation
